# cutmyvideo-web

Русский · [English](README.en.md)

[![Product checks](https://github.com/Kay0k1/cutmyvideo-web/actions/workflows/checks.yml/badge.svg)](https://github.com/Kay0k1/cutmyvideo-web/actions/workflows/checks.yml)
[![MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

Продуктовый веб-интерфейс [cutmy.video](https://cutmy.video) для ручного выбора моментов из видео и экспорта MP4, MP3 или MKV в режиме копирования. Работает с загруженными файлами и доступными публичными ссылками. Исходный код интерфейса открыт под лицензией MIT. Обработку медиа, HTTP API и очередь заданий предоставляет открытое MIT-ядро [cutmyvideo-core](https://github.com/Kay0k1/cutmyvideo-core).

## Использование

1. **Видео.** Вставьте публичную ссылку на отдельное видео, запись стрима или клип либо выберите MP4, MOV, MKV или WebM с устройства. Сайт показывает фактические название, длительность, сервис и ограничения из API. Неудачный импорт сохраняет прежнее видео и черновик.
2. **Момент.** Выберите аудиодорожку по индексу, языку и названию либо вариант «Без звука»: этот же выбор применяется к предпросмотру и экспорту. Укажите начало и конец на шкале, отметьте границы по позиции плеера и просмотрите результат. Точные поля времени и масштаб доступны отдельно. Поддерживаются секунды (`15`), минуты (`83:10`) и часы с миллисекундами (`01:23:10.250`).
3. **Фрагменты, если нужно.** Добавьте несколько моментов, подпишите их, выберите нужные для экспорта. Есть выбор всех, дублирование, удаление, перестановка и отмена/повтор правок. Для одного момента можно сразу перейти к экспорту.
4. **Экспорт.** Выберите MP4 или MP3, качество и режим; получите отдельные файлы либо один объединённый результат в порядке выбранного списка. При копировании видео доступны MP4 и MKV, в том числе для поддерживаемых площадок. Для загруженного файла или прямой ссылки также доступно сохранение совместимых текстовых субтитров. Сводка заранее показывает включённые и исключённые дорожки; результат содержит фактические границы и дорожки. Обработка продолжается при открытии другого видео; раздел «Экспорты и файлы» показывает последние задания, отмену и сохранённые результаты.

**Точные границы** перекодируют видео в H.264/AAC или звук в MP3. **Исходное качество** сохраняет совместимые потоки MP4/MKV без перекодирования; начало может сдвинуться к предшествующему ключевому кадру. Фактические границы указаны у готового файла. При частичной ошибке успешно созданные файлы остаются доступны.

Светлая, тёмная и системная темы, полный русский и английский интерфейс, клавиатурное управление, подписанные ползунки и видимый фокус работают на компьютере и телефоне. Каждое видео получает отдельный проект в браузере: фрагменты, их порядок, настройки, позиция и масштаб сохраняются при переключении и перезагрузке. Прежний общий черновик автоматически переносится в проекты. Язык, тема и настройки также сохраняются в браузере. Доступ к серверным файлам принадлежит текущей сессии: очистка cookies не восстанавливается из локального черновика.

На шкале доступны кадры текущего 30-секундного участка: нажмите кадр, чтобы перейти к нему. Подготовка шести миниатюр 160×90 запускается после паузы в перемотке, уступает воспроизведению и использует серверный кеш с теми же ограничениями ресурсов. Браузер хранит до восьми лент / 8 МиБ и освобождает их при смене источника. Проверка начала или конца проигрывает по 1,5 секунды с обеих сторон границы и останавливается; у начала и конца записи окно сокращается. В точных настройках есть кнопки ±0,1 с. Стрелки вне полей перематывают на 0,1 с, с Shift — на 1 с; I/O отмечают границы, пробел управляет воспроизведением. Не завершённый ввод времени сохраняется при перезагрузке. Если видео истекло, список с именами и точными границами остаётся в черновике: откройте ту же запись и явно включите восстановление фрагментов. Слишком короткая замена не удаляет сохранённые границы.

## Источники и ограничения

Распознаются YouTube, Twitch, Rutube, TikTok, Instagram, Vimeo, Dailymotion, VK Видео, Facebook, X/Twitter, Reddit, Одноклассники, Bilibili, Streamable и Rumble, а также публичные HTTPS-ссылки на файлы и страницы, поддерживаемые ядром. Короткие ссылки разрешает сервер.

Распознавание сервиса не гарантирует загрузку каждого ролика. Приватность, необходимость входа, географические ограничения и изменения платформы могут препятствовать импорту. Каналы, плейлисты, DRM и текущие прямые эфиры не импортируются. Обычная HTTPS-ссылка на медиафайл загружается целиком до обработки; поддерживаемые записи с платформ позволяют получать только необходимые участки с контекстом декодирования. Подробности и проверенные провайдеры — в [каталоге ядра](https://github.com/Kay0k1/cutmyvideo-core/blob/main/docs/providers.md).

Совместимые файлы воспроизводятся браузером напрямую, YouTube также может использовать встроенный плеер. Для остальных поддерживаемых источников и несовместимых кодеков сервер готовит 30-секундные участки предпросмотра, сохраняя шкалу всей записи. Уже просмотренные участки остаются в браузере в пределах 8 участков / 64 МиБ; следующий участок загружается заранее. Сервер повторно использует подготовленные участки после перезагрузки страницы: до 512 МиБ / 64 участков, с очисткой после 30 минут без обращения. Не просмотренное ранее место требует подготовки. При недоступном предпросмотре остаётся ручной ввод времени.

Лимиты настраивает оператор; интерфейс получает их из API. Конфигурация развёртывания в этом репозитории задаёт 32 ГиБ на исходный файл и получение с платформ за задание, 12 часов на фрагмент, 24 часа и 32 фрагмента на экспорт, 16 ГиБ на готовый файл. Локальный пример использует меньшие ограничения диска и файлов. «Экспорты и файлы» показывает до 30 последних заданий, активные — первыми. Большие скачивания поддерживают HTTP Range и длительное соединение. На сайте удаление исходника после полного успешного экспорта включено по умолчанию. Исходное медиа, предпросмотры, миниатюры и волна очищаются после завершения уже принятых операций. Проект в браузере и готовые клипы сохраняются; срок хранения клипов не меняется. Частичная ошибка или отмена не запускают эту очистку. Если отключить «Удалить исходник после экспорта», действует обычное серверное хранение: по умолчанию 24 часа, с продлением для используемых данных. Интерфейс показывает сроки, сообщённые сервером; для новой нарезки удалённую запись нужно открыть заново.

Выбор конкретной аудиодорожки доступен для загруженных файлов и прямых ссылок. Для видео площадки загрузите исходный файл; вариант «Без звука» работает и по ссылке. Сохранение текстовых субтитров доступно при копировании загруженного файла или прямой ссылки: время каждого фрагмента пересчитывается, оформление упрощается. ASS, SSA и графические субтитры не поддерживаются; точный режим исключает субтитры. MKV доступен для копирования видео из любого поддерживаемого источника. Копирование не меняет качество и может сдвигать границы до ключевых кадров. Ни режим, ни качество не меняются автоматически при несовместимости.

Потерянный ответ экспорта можно восстановить повтором сохранённого запроса даже после очистки исходника: сервер вернёт принятое задание по прежнему ключу, а не создаст дубль. Незавершённые повторы из версии 0.3 сохраняют исходное тело запроса и прежнюю политику хранения; для новых видео очистка по умолчанию включена.

## Кадр и звуковая волна

Настройка «Кадр» изначально свёрнута. Откройте её, чтобы выбрать исходные пропорции, квадрат, горизонтальный или вертикальный формат: 1:1, 16:9, 9:16, 4:3, 3:4, 3:2, 2:3, 4:5, 5:4 и 21:9. В «Своих пропорциях» задайте положительные ширину и высоту. Область можно перемещать и менять её размер на видео, кнопками или с клавиатуры; изображение не растягивается. Выбранный кадр применяется ко всем фрагментам проекта. Кроп доступен для точного MP4; при несовместимых настройках экспорт объясняет причину и предлагает явный выбор режима или сброс кадра.

Звуковая волна соответствует выбранной аудиодорожке и исходной шкале времени. Подробная шкала помогает увидеть речь и паузы; общий обзор постепенно заполняется участками, которые вы смотрели. Подготовка одного окна занимает не более 30 секунд исходного времени, начинается после паузы в перемотке и уступает воспроизведению. Браузер ограничивает кеш 256 окнами на текущую дорожку; сервер использует собственные лимиты, кеширование и очистку. В режиме экономии трафика запросы не выполняются. Источник без звука или недоступная волна не мешают ручной нарезке.

## Проекты и история правок

В шаге «Видео» откройте «Мои проекты», чтобы вернуться к прежней нарезке. Проекты хранятся в этом браузере без регистрации: удаление исходного медиа на сервере сохраняет интервалы, названия и настройки. Для продолжения откройте исходную запись и явно включите восстановление; при несовпадении названия, длительности, геометрии или идентификатора записи потребуется подтверждение. Доступ к файлам всегда проверяет сервер по текущей сессии.

«Скачать план» сохраняет выбранные фрагменты в порядке списка в строгом формате core plan v1. Серверные ID и ссылки в план не попадают. Для локальной CLI укажите путь к медиа в поле `input`; веб-интерфейс позволяет открыть JSON-план и затем выбрать соответствующую запись. Импорт в открытый проект требует подтверждения и доступен для отмены.

Кнопки вверх/вниз в списке меняют порядок, используемый при склейке и в плане. «Отменить изменение» / «Повторить изменение», Ctrl/Cmd+Z и Ctrl/Cmd+Shift+Z (также Ctrl+Y) действуют на границы, названия, добавление, дублирование, удаление, порядок и сохранённые настройки кадра. Одно перетаскивание или редактирование имени — одно действие. В текстовых полях сочетания сохраняют обычное поведение. История независима для каждого проекта и хранит до 50 действий в текущей вкладке; после перезагрузки сохраняется результат правок, а история начинается заново.

В браузере сохраняются до 100 проектов; JSON ограничен 4 194 304 символами, фактическая квота зависит от браузера. При недоступном хранилище или исчерпании квоты интерфейс предлагает скачать план; переход к другому видео блокируется, пока текущая работа не сохранена. При заполненном списке удалите ненужный проект перед открытием нового видео. Удаление проекта из браузера не удаляет серверные видео и результаты.

## Локальный запуск

Нужны Node.js 22 (минимум 20.19), Docker с Compose и Git. Репозитории должны находиться рядом. Команды ниже запускают отдельные локальные PostgreSQL, API и worker, затем интерфейс на `http://localhost:5173`.

```sh
git clone https://github.com/Kay0k1/cutmyvideo-core.git core
git clone https://github.com/Kay0k1/cutmyvideo-web.git web
cd web
git -C ../core checkout "$(cat core.version)"
printf 'POSTGRES_PASSWORD=%s\n' "$(openssl rand -hex 24)" > .env
chmod 600 .env
npm ci
docker compose --env-file .env -f deploy/compose.dev.yaml up --build -d --wait
npm run dev
```

Настройки доступны в [.env.example](.env.example). Если открываете интерфейс по `http://127.0.0.1:5173`, задайте такой же `PUBLIC_ORIGIN` в `.env` и пересоздайте локальные API/worker. Vite передаёт `/api` на `127.0.0.1:8080`; сайт, плеер и скачивание используют один origin. Локальная база данных не публикует порт, API доступен только через loopback. Для проверки работоспособности:

```sh
curl --fail http://127.0.0.1:8080/readyz
docker compose --env-file .env -f deploy/compose.dev.yaml ps
```

Остановить локальные сервисы, сохранив базу и медиа:

```sh
docker compose --env-file .env -f deploy/compose.dev.yaml down
```

Если ядро уже запущено вручную, нужны оба процесса: `cutmy server` и `cutmy worker`, общие база/`DATA_DIR` и `PUBLIC_ORIGIN` сайта. При работе над ядром не переключайте изменённый checkout командой из инструкции: `core.version` фиксирует версию для CI, а локально можно проверять свои изменения.

## Проверки

```sh
npm test
npm run build
npm run test:deploy
```

Сборка включает проверку TypeScript. Браузерные проверки используют настоящее ядро и FFmpeg, создают синтетические видео, вырезают и декодируют реальные MP4/MP3, проверяют восстановление, отмену, сессии, клавиатуру и адаптивность. Для них используйте одноразовую базу и каталог медиа с [настройками тестовых ограничений](docs/QA.md#running-the-integrated-checks): полный набор не предназначен для обычной рабочей базы.

```sh
npx playwright install --with-deps chromium firefox webkit
npm run test:e2e -- --project=desktop --project=mobile
```

CI запускает unit/build/deploy и аудит всех npm-зависимостей, проверяет роли PostgreSQL с настоящим ядром, а затем интеграцию и удобство интерфейса в Chromium/Firefox на Linux и WebKit на macOS. Версия ядра фиксируется в [core.version](core.version), зависимости и образы закреплены. Готовая сборка сайта сохраняется как артефакт CI. На Linux у WebKit известна нестабильность GTK/GStreamer после перемотки; полный медианабор CI выполняется на macOS. Дополнительные сетевые провайдеры и трёхчасовой файл включаются отдельно; результаты и ограничения описаны в [QA](docs/QA.md).

Версия cutmyvideo-core закреплена в [core.version](core.version). Production-образ сохраняет версию, commit и время сборки именно закреплённого ядра. В отдельной одноразовой базе Linux CI блокирует учёт хранилища и проверяет настоящий ответ `503 database_unavailable`: сохранение выбранного фрагмента, отсутствие автоматической повторной отправки и один экспорт после осознанного повтора с прежним ключом. Эти сценарии требуют явного режима `CUTMY_E2E_DATABASE_CONTROL=hosted-disposable` и отказываются работать вне одноразового GitHub runner; обычная разработка их пропускает.

## Размещение

[DEPLOYMENT.md](docs/DEPLOYMENT.md) описывает HTTPS, внутреннюю сеть, ограничения, резервные копии, мониторинг, обновление и откат. Production Compose отличается от локального примера. Dockerfile собирает статический сайт; внешний reverse proxy передаёт `/api` в ядро. Release helper проверяет чистоту обоих репозиториев и совпадение с `core.version`, собирает релиз из Git, проверяет здоровье сервисов и откатывает неудачную активацию, сохраняя постоянные volumes. Запуск этого helper выполняет реальное обновление настроенного сервера.
